# Second review round, 2026-08-01

Disposition of the findings from the 2026-08-01 review. The first round is in
`review-2026-07-30.md`; that table describes the state on its own date and is
no longer current (finding 22's alias guard in particular).

Metric conventions are unchanged: references are mpmath at ≥ 40 dps, bars sit
at ~4x the measured worst case, and the per-family error metric is the one in
each test file's docstring.

## Release blockers

| # | Finding | Disposition |
|---|---|---|
| B1 | Adaptive fitting could certify an aliased polynomial: `_validated` sized its grid from the CANDIDATE, so it could recreate the fitting grid. `fit(T29, dps=60)` returned −T₅, dense sup error 2.0 | `_validated` now takes the fitting resolution n and checks `chebpts(2n)` and `chebpts(4n)`. Those three grids are pairwise disjoint by construction (`chebpts(p)` and `chebpts(q)` share a point only when p/gcd and q/gcd are both odd), and no mode below 15n+1 folds to the same (index, sign) on all three, so an alias shows an O(scale) error on at least one. The zero-scale shortcut and never-truncated candidates go through the same check. Sweep k = 1..70 at dps=60: degree k every time, worst sup error 7.2e-15 (5.6e-60 on the tighter re-run) |
| B2 | The inverse suite was unreliable under jax's DEFAULT x64-off configuration: `betaincinv(10,10,.5)`, `gammaincinv(20,.1)`, `gammaincinv(100,.5)`, `stdtrit(20,.1)` all returned nan | The log-space brackets, iteration counts and residual bars now derive from the canonical dtype's own exponent range (−708/709 in float64, −87/88 in float32) instead of hard-coded float64 edges. New `tests/test_x64_off.py` covers the public API in child processes, and CI gained an `x64-off` job so the default configuration cannot regress unseen |
| B3 | `gammaincinv` missed its all-positive-shape and upper-tail contract: `gammaincinv(100, 1e-20)` → nan; a=1 at p=nextafter(1,0) → 35.7498 instead of 36.7368; a ≤ 0 silently returned 0 | The upper half solves against Q / ln Q, the residual scales with min(p, 1−p), and nonpositive or nonfinite shapes return nan on every path including the endpoints (`chi2inv` inherits it). All reported cases now match mpmath |
| B4 | Student-t tails lost to unstable algebra: `stdtr(.2, -1e154)` → 0 (true 5.96e-32); `stdtrit(4, 1e-20)` → −inf (true ≈ −131607) | The forward tail is formulated through log\|t\| so t² never overflows, and the inverse takes the lower tail directly as 2p instead of 1 − \|2p − 1\|. Added `log_stdtr` / `log_stdtr_sf`, the Student-t log-CDF and log-survival, exported from `chebax` |
| B5 | All three numpyro truncations collapsed in narrow or deep tails: Gamma(3) on [50,51], Beta(2,3) on [.999999,.9999999] and Student-t(4) on [1e5,2e5] each gave (flo, fhi) = (1,1), then log_prob +inf, cdf nan | A shared `_Truncated` base normalizes entirely in logs: ln Z from a stable `logdiffexp` over a log-CDF / log-survival pair taken in whichever tail holds both endpoints, with icdf targeting a matching one-sided probability. Gamma's upper tail needed a survival-inverse solve that `gammaincinv` cannot express. Worst relative error against mpmath over eight deep-tail cases 1.7e-13; ordinary cases unchanged at 1.3e-14. The KS tests now use an independent scipy truncated CDF instead of the distribution's own `cdf` |
| B6 | Default one-sided `TruncatedGamma` had nan rate gradients (`rate * high` formed before masking high = inf) | Every endpoint is masked to a safe interior value before any arithmetic. Reverse and forward mode now agree with central differences across 42 (parameter, function) combinations |
| B7 | `besseli_ratio` divided two independently underflowing scaled functions: nan at (8.9, 1e-6) under x64 off, nan at x = inf, and a forced-zero origin gradient where the slope is 1/(2(ν+1)) | An ascending-series branch below x = 2 cancels the (x/2)^ν and Γ(ν+1) prefactors analytically, so nothing underflows; explicit limit 1 at x = inf; a boundary JVP makes the origin slope exactly 1/(2(ν+1)) (1/2 for von Mises) |
| B8 | Order differentiation was unstable just above ν = 0: wrong SIGN at ν=1e-16, x=30; ~20% factory and 137% traced error at ν=1e-14, x=100 | dI/dν near ν = 0 is rebuilt from the tables' second ν-derivative rather than the amplifying `I · dlogI/dν` path. Factory and traced paths now agree with mpmath on a logarithmic order grid down to ν = 1e-16 |
| B9 | Incomplete-gamma IEEE endpoints: for a ≥ 1 all four of P, Q, ln P, ln Q returned nan at x = +inf; the claimed exact x-derivative was masked to 0 at x = 0 including a = 1 | x = +inf is masked out of the tail bracket and the limits (1, 0, 0, −inf) are set by hand. An endpoint-slope rule splices the true Gamma density into dP/dx at x = 0: 1 at a = 1, 0 above, +inf below |

## Other findings

| Finding | Disposition |
|---|---|
| Large finite arguments overflowed internally: scaled I₀(1e308) → 0, `log_besselk_fn` → −inf | Both split the product and the logarithm before evaluating. `2*x` overflowing above x ≈ 9e307 was the shared cause |
| `vonmises_icdf` lacked residual enforcement (κ=50, p=1e-15 landed at CDF 3.7e-14) | It now checks its residual AND its resolvability. F is accurate absolutely, so a converged solve can only promise ~32 eps / min(p, 1−p) relative; below min(p, 1−p) = 4096 eps the quantile returns nan. That floor is set by the CDF's representation, so it does not move with κ (an earlier density-based floor did, and wrongly kept a 4% answer at κ=2 while rejecting a 1e-7 one at κ=50) |
| bake's "runtime cannot diverge" was too strong; names unsanitized; nonfinite coefficient arrays emitted invalid literals; C++ `sign(NaN)` diverged | Artifacts now DECLARE their dtype and reject any other input rather than silently following it. Names are validated, nonfinite tables rejected at bake time, and the remaining honest gaps (float32 is the f64 computation carried out in f32, dtype-dependent branches, and one-sided endpoint slopes) are stated in the docstring |
| `pergroup` evaluated padded empty groups, so reverse mode could produce 0·NaN | Empty groups borrow a live group's element and parameters before the vmap, so `fn` only ever sees a live (param, x) pair. Verified with an out-of-domain parameter and with a nan parameter, in both AD modes |
| Cached public Recipe instances were mutable, so changing one corrupted later calls from the same cache slot | `Recipe`, `ChebSeries` and `PiecewiseCheb` freeze after construction and raise on attribute assignment. Pytree flatten/unflatten, jit, grad, vmap, `astype` and `truncate` are unaffected |
| Unbounded dense O(n²) derivative/integral matrix caches in `series.py` | Replaced by direct O(n) Chebyshev recurrences that work on tracers |
| `fit` needed front-loaded validation; explicit `deg` could exceed `max_deg` | deg, tol, max_deg, dps, breaks and domain are validated before f is ever sampled, each with a ValueError naming the argument. A fixed `deg=` stays deliberately unvalidated for aliasing (an unresolved f at a fixed degree is a legitimate request) and the docstring now says so |
| Coefficient conversion was lossy for large integers under x64 off, silently dropped complex parts, and allowed integer `astype` targets | int64 input no longer wraps through int32 (2⁵³+1 used to become 1.0), complex coefficients raise, and `astype` requires a floating dtype |
| The no-argument erf-family cache retained f32 coefficients after x64 was enabled | Given the same dtype tag the parameterized caches already use |
| numpyro endpoint densities returned nan for finite cases; `validate_args=True` rejected TruncatedStudentT's own infinite defaults; table ranges and scalar-shape requirements unencoded; icdf endpoints not exact | All fixed: the finite endpoint densities are spliced in by hard select, bounds use an inclusive interval constraint, the documented domains and the uniform-per-call contract are checked at construction (pointing at `chebax.pergroup`), and icdf(0)/icdf(1) return `low`/`high` exactly |
| pytensor `GammaIncCInv` solves at 1 − p, so upper-tail probabilities below ~1e-17 become inf | The limitation was documented only in the module; it is now stated in the README next to the integration claim |

## Documentation and coherence

- `review-2026-07-30.md` no longer claims all findings are closed, and points here.
- `increments.md` no longer says `gammaincinv` uses no tables (increment 17 rewired it).
- The notebook job executes eight notebooks; the "nine" claim is corrected.
- Notebooks 02, 03, 06 and 07 use `chi2inv`, `besseli_ratio` and `log_betainc_fn`
  instead of hand-rolling them.
- The README no longer says the erf family is "kept for the C++ bake path":
  `bake` takes Recipe instances and `dawsn`/`erfcx` are plain functions.

## Not addressed

- `_chop`'s noise floor still reads the last sixteenth of the coefficients, so a
  function whose top mode sits inside that window gets `2·|c_top|` as its level
  rather than a noise estimate: `fit(T20, max_deg=20, dps=40)` still raises even
  though the 21-point fit is exact. Pre-existing, and retuning `_chop` moves the
  oscillatory cases the current tests pin.
- A TruncatedGamma with concentration outside chebax's [0.1, 10] box falls back
  to jax's `gammainc`, whose logs still underflow, so a deep upper-tail
  truncation there is not fixed.
- The gamma survival-inverse lives in `chebax/numpyro.py`. It is a real solver in
  what was a wiring module and belongs in `quantiles.py` as a public
  `gammainccinv`.
