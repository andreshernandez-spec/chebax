# Third review round, 2026-08-02

Disposition of the findings from the 2026-08-02 review, which read
`review-integration` at 0422d3b. The earlier rounds are in
`review-2026-07-30.md` and `review-2026-08-01.md`; both describe the state
on their own dates, and B1 of the second one was CLOSED IN ERROR (see
below).

Metric conventions are unchanged: references are mpmath at ≥ 40 dps, bars
sit at ~4x the measured worst case, and the per-family error metric is the
one in each test file's docstring.

## Release blockers

| # | Finding | Disposition |
|---|---|---|
| B1 | Adaptive fitting still certifies aliased fits: the validation grids n, 2n and 4n are harmonically related and T_{16n} is exactly +1 on all three, so `fit(T272)` returned degree 0 with coefficient 1.0, dense sup error 2.0. The 2026-08-01 closure bounded the smallest common alias and said nothing about the family above it; the regression sweep stopped at frequency 70 | Validation now runs on `cos(pi (i + PHI)/m)` with PHI irrational, which are the nodes of no Chebyshev grid at all: an alias there needs `(K -+ j)(i + PHI)/m` in 2Z for every i, which forces `K -+ j = 2mq` and then `2qPHI` in Z, so q = 0. The 2n grid is kept because it is cheap, not because it carries the argument. The docstring now says what a finite point set can promise, which is gross-error detection. Fixing it exposed a second defect: the allowance ignored the Clenshaw evaluation floor, which grows with degree, so an honest degree-544 fit (6e-13 off its own exact samples) was being rejected once the off-grid sets started looking. T_{16n} for n = 17 at k = 68, 136, 272, 544 all return degree k, worst sup error 2.2e-13 |
| B2 | `gammaincinv` missed its all-positive-shape contract outside the table range: 5000/0.05, 4000/0.10 and 10000/1e-8 all nan under default float32 | Closed by increment 29 (merged the same day, PR #21): the Temme-zone tables run to a = inf, so those shapes never reach the jax fallback. Verified at the reported points: float32 to 3.5e-7, float64 to eps |
| B3 | Generic bake silently changed custom-JVP semantics: `_is_constant_zero_jvp` accepted any rule whose primal is a zero literal, so a rule with derivative 1 baked to 0 while the artifact still said plain AD gives the derivative. `endpoint_slope_dropped` was recorded and never surfaced | The fold takes chebax's own `edge_slope` by function name AND defining module, and separately evaluates the primal to confirm it is identically zero. Either check alone is unsafe: the name says the author accepted the cost, the evaluation says no value can change. Everything else non-series was already refused. Both emitters now disclose a dropped endpoint slope in the artifact itself |

## High-priority findings

| Finding | Disposition |
|---|---|
| Python integer parameters broke differentiation systemically: `grad` through `besseli_fn(2, x)`, `stdtr(4, t)`, `stdtrit(4, p)` and `vonmises_cdf(5, t)` all failed on float0 tangents | One policy, `_common.float_params`: the custom_jvp rule lives on a private name and the public entry point promotes every argument first, so the parameter is an ordinary float constant before a tangent exists. Doing it inside the rule cannot work, since by then the float0 is already there. `besseli_ratio`, `log_stdtr` and `log_stdtr_sf` had it too. `tests/test_int_params.py` is the contract matrix: 20 public functions x python and numpy integers x value, gradient and jit |
| `TruncatedBeta` rejected the widened box: the class documented [0.1, 100]² while its constraints imported the [0.1, 10] panel constant | `chebax/domains.py` holds each family's box, read off the table module that governs the computation, and the recipes' range checks, the numpyro constraints and eager checks, and the pytensor box all consume it. `TruncatedBeta(20, 3)` works; the obsolete test that codified the rejection is gone |
| pytensor `Kve` lost its scaled asymptotic: `exp(log K + x)` cancels -x against +x and takes the -½ln x with it, so `Kve(2.5, 1e20)` was 1.0 for a true 1.2533141373e-10 | `besselk_fn(nu, x, scaled=True)` returns the tail table's own quantity, e^x K, with no e^-x factor to reinstate. Measured against mpmath below x = 500 and the asymptotic series above: worst 2.1e-15 out to x = 1e300 |
| The deep-tail `stdtrit` shape gradient overflowed: at nu = 4, p = 1e-300 the value is finite but d/dnu was inf, for a true 5.66e76 | The shape direction goes through the logs: dF/dnu = F dlnF/dnu, so the ratio is `exp(lnF - ln pdf) dlnF/dnu` and nothing underflows on the way. The probability derivative 1/pdf may legitimately overflow and still does. Worst 2.4e-7 against central differences, which is the difference step's own floor |
| Endpoint differentiation was inconsistent: `betainc_fn(1,3,·)` at 0 and `betainc_fn(3,1,·)` at 1 gave 0 for a true 3, `hyp1f1_fn(2,3,·)` at 0 gave 0 for a true 2/3, and `hyp1f1_fn(1,1,inf)` was nan | gammainc's zero-carrying rule generalizes and moved to `_common.edge_slope`; betainc splices its endpoint densities through it (b at 0 when a = 1, a at 1 when b = 1, 0 above, inf below). hyp1f1 needed no splice: letting x = 0 ride the inner lane gives log1p(0) = 0, the same value with the right slope, so the select went away. M at +inf is set by hand in both forms, the tail bracket being inf + (a-b)inf |

## Documentation and coherence

All the named drift is corrected: `review-2026-08-01.md`'s B1 row now
records that its closure was wrong and points here; PROJECT.md's status
paragraph counts thirty-one increments and no longer lists the betainc
widening, the wide-beta box or gammainc above 10 as open; `betainc.py`'s
log form says [0.1, 100]²; `gammainc.py` says a ≥ 0.1 with no upper end;
`numpyro.py` no longer claims the Student-t log-CDF is unexported; hyp1f1
no longer documents an incorrect origin gradient, because it no longer has
one.

Of the review's three structural recommendations, two are in: central
public domain metadata (`chebax.domains`) and one parameter-canonicalization
policy (`_common.float_params`). The third, a contract matrix over
endpoints, infinities, nans, integers and both dtypes, exists as
`tests/test_int_params.py` and `tests/test_contracts.py` and is the place
to extend rather than scatter the next round's cases.

## Not addressed

- The unscaled `besseli_dnu` at x = +inf is still nan. The value there is
  itself infinite and the order derivative tends to -inf for v > 0, so
  there is a limit to return, but the review asked only about the scaled
  form and inventing the unscaled contract here is not obviously right.
