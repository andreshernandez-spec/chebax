Verdict
I reviewed review-integration at 0422d3b. The branch is substantially better, and most earlier fixes are real, but I would not consider the review fully integrated or release 0.3.0 from this state. Three correctness issues still contradict central library contracts.
Release blockers
Adaptive fitting still certifies aliased fits.
[`_validated` (line 126)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/generate.py:126) checks harmonically related n, 2n, and 4n Chebyshev grids. \(T_{16n}\) is exactly +1 on all three. With the initial n=17:
fit(lambda x: cos(272 * arccos(x)))
returns degree zero with coefficient [1.0]; dense sup error is approximately 2.
The argument in [review-2026-08-01.md (line 15)](/home/ahernandez/private/open-source/chebax/docs/review-2026-08-01.md:15) only excludes common aliases below a frequency bound, but an unrestricted source callable has no such bound. The regression sweep stops at frequency 70 and therefore misses this family.
Use off-grid or non-harmonically related validation points, add \(T_{16n}\), and document finite validation as a gross-error heuristic—not a proof.

gammaincinv still does not meet its all-positive-shape contract.
Outside the table range, [`gammaincinv` (line 350)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/quantiles.py:350) falls back to logs of JAX’s incomplete-gamma functions at [quantiles.py (line 315)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/quantiles.py:315). On current HEAD under default float32:
gammaincinv(5000, 0.05)  -> nan
gammaincinv(4000, 0.10)  -> nan
gammaincinv(10000, 1e-8) -> nan
All have finite SciPy references. Failures appear non-monotonically across shapes 3,000–10,000 at ordinary probabilities. Float64 also fails just outside the table boundary for some deep probabilities.
Either harden the native fallback and test shapes beyond 1,000 in both dtypes, or honestly restrict the public contract to the supported table range. chi2inv inherits this issue.

Generic bake silently changes custom-JVP semantics.
[`_is_constant_zero_jvp` (line 186)](/home/ahernandez/private/open-source/chebax/src/chebax/bake/_jaxpr_emit.py:186) assumes every custom JVP with a literal-zero primal represents an endpoint-only slope, then emits ordinary zero at [_jaxpr_emit.py (line 221)](/home/ahernandez/private/open-source/chebax/src/chebax/bake/_jaxpr_emit.py:221).
A minimal Recipe returning zero with a custom derivative of one has runtime gradient 1 everywhere but baked gradient 0. The built-in gammainc(1) similarly loses its origin slope. Yet generated modules state “Plain jax AD gives the derivative” at [bake/__init__.py (line 165)](/home/ahernandez/private/open-source/chebax/src/chebax/bake/__init__.py:165). endpoint_slope_dropped is recorded but never reaches the generated documentation.
Unknown non-series custom JVPs should be rejected. If the gamma endpoint helper remains an exception, it needs a narrow explicit protocol and the generated artifact must disclose the derivative difference.

High-priority findings
Ordinary Python integer parameters break differentiation systemically.
These common calls fail:
grad(lambda x: besseli_fn(2, x))(3.0)
grad(lambda t: stdtr(4, t))(1.0)
grad(lambda p: stdtrit(4, p))(0.3)
grad(lambda t: vonmises_cdf(5, t))(0.3)
Integer primals produce float0 tangents, which are used as numeric arrays in the custom JVPs at [besseli.py (line 284)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/besseli.py:284), [quantiles.py (line 524)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/quantiles.py:524), and [vonmises.py (line 77)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/vonmises.py:77).
Put the custom JVP on a private function and canonicalize public real parameters before calling it, or provide one shared symbolic-zero/float0 normalization helper. Add Python and NumPy integer cases to every traced-parameter test matrix.

TruncatedBeta rejects the newly supported wide domain.
The class documents [0.1, 100]², while its constraints and eager checks at [numpyro.py (line 378)](/home/ahernandez/private/open-source/chebax/src/chebax/numpyro.py:378) still import _bt.AHI == 10. TruncatedBeta(20, 3) therefore raises even though the core wide-panel implementation supports it. The test at [test_numpyro_module.py (line 414)](/home/ahernandez/private/open-source/chebax/tests/test_numpyro_module.py:414) currently codifies the obsolete rejection.
This is a strong example of why public domain metadata should be centralized rather than imported from an implementation panel.

PyTensor Kve loses its scaled asymptotic at large finite arguments.
[pytensor.py (line 155)](/home/ahernandez/private/open-source/chebax/src/chebax/pytensor.py:155) computes:
exp(log_besselk_fn(v, x) + x)
At large x, rounding cancels the -x + x terms and loses the remaining -½ log(x) dependence:
Kve(2.5, 1e20)  -> 1.0
reference        -> 1.2533141373e-10
Evaluate the scaled tail directly, or expose a native scaled-K/log-scaled-K primitive.

The deep-tail stdtrit shape gradient overflows spuriously.
At nu=4, p=1e-300, the quantile is correctly finite:
value       = -1.31607401295e75
d/dnu       = inf
finite diff = 5.65534136e76
The JVP at [quantiles.py (line 643)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/quantiles.py:643) separately forms an underflowed density and dF/dnu, even though their ratio is finite. Compute the shape IFT through log-CDF/log-density derivatives. The probability derivative may legitimately overflow; the shape derivative does not here.

Endpoint differentiation remains inconsistent across recipes.
In particular:
grad(lambda x: betainc_fn(1,3,x))(0) returns 0, not the exact density 3.
grad(lambda x: betainc_fn(3,1,x))(1) likewise returns 0, not 3.
grad(lambda x: hyp1f1_fn(2,3,x))(0) returns 0, not 2/3.
hyp1f1_fn(1,1,+inf) and its log form return nan, not +inf.
The hard selects are at [betainc.py (line 140)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/betainc.py:140) and [hyp1f1.py (line 78)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/recipes/hyp1f1.py:78). Beta documentation even claims the endpoints are masked to the interior limits, which is not what JAX differentiates.
The gamma endpoint repair provides a good pattern to reuse.

Medium-priority findings
Bake coverage is narrower than advertised. Public closed-form recipes still fail: besseli_dnu(2.5) encounters a dead empty primitive, while large-parameter gammainc/gammaincc encounter unsupported erfc. Skip dead DropVar equations, support erfc, and test every public Recipe class and panel.

Cached immutability can be bypassed with deletion. ChebSeries and PiecewiseCheb protect assignment at [series.py (line 161)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/series.py:161) and [series.py (line 265)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/series.py:265), but lack __delattr__. Deleting a coefficient from one cached instance corrupts all callers sharing it.

Finite extreme domains overflow internally. The affine map at [series.py (line 113)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/series.py:113) accepts (-1e308, 1e308) but produces nan at both endpoints; derivative scaling becomes zero. Equivalent formulas recur in piecewise evaluation, generation, and bake. Use stable midpoint/half-width algebra.

truncate() does not validate its tolerance. At [series.py (line 187)](/home/ahernandez/private/open-source/chebax/src/chebax/_src/series.py:187), negative tolerances are silent no-ops, while nan or inf silently collapse a nonconstant series to degree zero. Require finite, nonnegative input before bake forwards it.

C++ naming validation uses Python rules. [bake/__init__.py (line 62)](/home/ahernandez/private/open-source/chebax/src/chebax/bake/__init__.py:62) accepts name="template"; the emitted header then fails to compile. Validate C++17 keywords and reserved identifier forms separately.

Exact fits at the hard degree cap still fail. As already documented, fit(T20, max_deg=20) and even fit(T1, max_deg=1) raise. Sampling above the return cap would let _chop distinguish a top mode from its noise estimate.

Invalid inverse-CDF probabilities are mapped to plausible bounds. _Truncated.icdf(-0.1) returns low and .icdf(1.1) returns high at [numpyro.py (line 288)](/home/ahernandez/private/open-source/chebax/src/chebax/numpyro.py:288), unlike the core quantiles’ NaN policy. Mask invalid values before logarithms and return NaN outside [0,1].

Additional IEEE/domain gaps remain: matern(..., +inf) and spherical Bessel functions at +inf return NaN instead of zero; negative Matérn distances silently return one; scaled Bessel-I order derivatives at infinity return NaN instead of zero.

Some front-door validation remains permissive: malformed fit(domain=...) tuples produce IndexError or silently ignore elements, and pergroup(..., num_groups=2.9) silently truncates to 2.

Documentation and architectural coherence
The numerical comments are generally excellent: they explain why formulas are arranged as they are and record useful empirical failure cases. The weakness is that contracts and historical measurements are mixed together, making drift easy.

I recommend three shared mechanisms:
Central public domain metadata, consumed by recipes, integrations, constraints, and documentation.
One parameter-canonicalization and symbolic-zero policy for every custom JVP.
A contract test matrix covering endpoints, infinities, NaNs, Python integers, both dtypes, and one point immediately inside/outside every table boundary.
The private gamma survival inverse in numpyro.py should also become a public gammainccinv in quantiles.py. That would remove duplicated solver logic and fix the documented PyTensor GammaIncCInv precision limitation.
