# Code review 2026-10-26

Reviewed `dcdb931` across the core, recipes, baking, integrations, tests, and
contributor documentation. The implementation has a useful separation between
high-precision construction and JAX evaluation, immutable cached objects, and
strong per-family accuracy evidence. Its main weakness is inconsistent input
and automatic-differentiation contracts at the boundaries between those parts.
Several tests also fail to reject unexpected NaNs.

The findings below describe `dcdb931`; how each was resolved is in the
[last section](#disposition). P1 means a high-priority failure of a principal supported use case. P2 means
an actionable correctness defect in a supported input or mode.

## Confirmed correctness findings

### R1 P1 Deep-tail NumPyro likelihoods have NaN gradients

Location: [`numpyro.py:176`](../src/chebax/numpyro.py#L176).

With x64 enabled:

```python
from chebax.numpyro import TruncatedGamma

f = lambda c: TruncatedGamma(c, low=1000., high=1001.).log_prob(1000.5)
f(3.)             # -0.041161055681186554
jax.grad(f)(3.)   # nan
```

The 50-dps reference derivative is `0.00008182020317094208818`.
The lower-tail interval `[1e-200, 2e-200]`, evaluated at `1.5e-200`, also
has a finite log density and a NaN shape gradient. The inactive difference
of log probabilities rounds to two equal zeros, and both `_logdiffexp`
branches are evaluated before `where` selects one. Its singular derivative
contaminates reverse AD. This breaks the advertised deep-tail inference use
case even when the selected normalizer is well resolved. Mask the inactive
operands before evaluating the log difference, and cover deep-tail gradients.

### R2 P2 Accuracy sweeps can pass with NaN results

Locations: [`test_tweedie.py:198`](../tests/test_tweedie.py#L198) and
[`test_tweedie.py:213`](../tests/test_tweedie.py#L213), with the same reduction
pattern in other family tests.

Python's `max(0.0, float('nan'))` returns `0.0`. These tests aggregate errors
with `max(worst, error)` and assert only the final bound, so NaN results are
silently discarded. In a temporary in-memory check, replacing
`chebax.tweedie_logpdf` with `lambda p, mu, phi, y: jnp.nan * mu` let both
the value and mean-gradient accuracy tests pass for an ordinary finite case,
despite both the value and gradient being NaN. Assert finiteness before error
aggregation, and audit other scalar worst-error loops.

### R3 P2 Keyword arguments bypass shared parameter normalization

Location: [`_common.py:107`](../src/chebax/_src/recipes/_common.py#L107).

```python
jax.grad(lambda t: chebax.stdtr(nu=4, t=t))(.3)  # raises
chebax.stdtr(nu=jnp.array([4.]), t=.3)          # coefficient-shape error
```

The corresponding positional calls work. `float_params` normalizes only
`args`, forwards `kw` unchanged, and skips scalar normalization for fewer
than two positional arguments. Keyword integers reach custom JVPs with
`float0` tangents; keyword size-one arrays bypass the uniform-parameter
policy. The same problem affects other wrapped functions, including
`log_stdtr`, `stdtrit`, and `vonmises_cdf`. Normalize bound named arguments at
one public boundary, preserving the signature and actual parameter names.

### R4 P2 Size-one inverse parameters work for values but fail under AD

Locations: [`quantiles.py:275`](../src/chebax/_src/recipes/quantiles.py#L275),
[`quantiles.py:455`](../src/chebax/_src/recipes/quantiles.py#L455), and the
corresponding `gammainccinv` JVP.

```python
a = jnp.array([2.])
chebax.gammaincinv(a, .3)                   # scalar value
jax.grad(lambda p: chebax.gammaincinv(a, p))(.3)
# custom JVP expected a scalar tangent, got shape (1,)
```

Also reproduced for `gammainccinv(a, p)` and `betaincinv(a, 3., p)`.
The primal squeezes the parameter inside the custom-JVP function, while
the rule's density computation preserves its original shape. Normalize
before entering the custom JVP and extend size-one contract tests to AD.

### R5 P2 Integer evaluation points break coefficient differentiation

Locations: [`series.py:155`](../src/chebax/_src/series.py#L155) and the
piecewise JVP at line 269.

```python
jax.grad(lambda c: chebax.ChebSeries(c)(1))(jnp.array([1., 2.]))
# TypeError: Called multiply with a float0 array
```

Using `1.` returns `[1., 1.]`. The same failure occurs for `PiecewiseCheb`
with an integer evaluation point. Integer `x` reaches the custom JVP before
promotion, even though differentiation targets floating coefficients.
Promote evaluation points at the series call boundary.

### R6 P2 Group padding corrupts infinite endpoint gradients

Locations: [`pergroup.py:87`](../src/chebax/_src/pergroup.py#L87) and
[`pergroup.py:110`](../src/chebax/_src/pergroup.py#L110).

```python
g = chebax.pergroup(chebax.betainc_fn, [0, 0, 1])
a, b = jnp.array([.5, .5]), jnp.array([2., 2.])
x = jnp.array([.2, .3, 0.])
jax.grad(lambda x: g(a, b, x).sum())(x)
# [1.34164079, .95851448, nan], expected last entry +inf
```

Ragged groups pad by repeating a live element. An unused duplicate of a
singular endpoint receives zero cotangent, forming `0 * inf` and contaminating
the original element's gradient. Fixing empty groups did not fix this case.
The generic example `pergroup(lambda a, x: a * jnp.sqrt(x), [0, 0, 1])`
has the same defect. Padding needs a differentiation policy that cannot
contribute undefined products from unused lanes.

### R7 P2 Baking restores the overflow-prone coordinate map

Location: [`_jaxpr_emit.py:298`](../src/chebax/bake/_jaxpr_emit.py#L298).

The series runtime uses midpoint and half-width for finite extreme domains.
The emitter substitutes `(2*x - (b+a)) / (b-a)` instead. A custom `Recipe`
wrapping `ChebSeries([0., 1.], (-1e308, 1e308))` returns `1.` at `1e308`,
but its emitted Python contains division by bare `inf` and raises `NameError`.
The C++ output also contains an undeclared `inf`. Use the same stable map as
the runtime and exercise the generic recipe extension point in bake tests.

### R8 P2 Accepted artifact names produce unusable output

Location: [`bake/__init__.py:193`](../src/chebax/bake/__init__.py#L193),
with generated globals at lines 213, 222, and 230.

`bake.jax_module(chebax.besselj(2.5), path, name='jnp')` succeeds, but the
emitted function replaces the imported `jnp` module and fails when called.
`name='_clenshaw'` overwrites the emitted helper and also fails. Valid
language identifiers are insufficient; reserve emitter dependencies or isolate
their namespace. Separately, the default C++ name for
`besselj(2.5, domain=(0, 8))` includes its tuple metadata and is rejected by
the identifier validator. Default naming must encode structured statics.

### R9 P2 PyTensor BetaInc changes derivative behavior

Location: [`pytensor.py:280`](../src/chebax/pytensor.py#L280) through line 293.

For `_betainc_scalar_ab(150., 3.5, .4)`, an x-only forward JVP returns NaN
while reverse AD returns the finite density `1.8182069771298108e-53`.
The documented unavailable shape derivatives are set to NaN, then multiplied
by zero shape tangents, poisoning an independent supported derivative.
Handle inactive directions without multiplying their undefined partials.

The same rule clips x before computing the density. At `(a,b,x)=(.5,2.,0.)`
its reverse x derivative is about `5.03e153`; at `(2.,.5,1.)` it is about
`5.03e7`. Both limits should be positive infinity. Preserve endpoint density
limits explicitly and compare forward and reverse modes against the core
recipe. The out-of-box forward-mode reproduction was also checked with JIT
disabled to avoid tracing the unused table branch.

### R10 P2 Tweedie deviance loses accuracy near the mean and overflows in tails

Location: [`tweedie.py:145`](../src/chebax/_src/recipes/tweedie.py#L145)
through line 151.

The default float32 path loses substantial accuracy for concentrated densities:

| Call arguments `(p, mu, phi, y)` | Actual log density | Reference |
| --- | --- | --- |
| `(1.5, 1e6, 1e-8, 1000010.)` | -6.6177115440 | -7.07021357982138 |
| `(1.5, 1e6, 1e-12, 1000000.125)` | 2.5349388123 | -5.27756049918239 |

The independent 70-dps reference uses the identity
`Phi(1, 0; z) = sqrt(z) * I1(2*sqrt(z))`. Subtracting nearby logarithms
loses the relative displacement, and subtracting two first-order `expm1`
terms to recover a quadratic deviance loses more digits. Use a relative
displacement, `log1p`, and a quadratic expansion near the mean. Current tests
use dispersion at least `.05` and cap the saddle scale at `1e5`, missing
these concentrated cases.

There is also an overflow in the same deviance computation under x64:

```python
chebax.tweedie_logpdf(1.5, 1e-300, 1., 1e10)  # nan
```

`y / mu` overflows, although the log density is finite, dominated by
`-2e160`. At p = 1.5 the half-deviance is exactly
`2*y/sqrt(mu) - 4*sqrt(y) + 2*sqrt(mu)`, which establishes the finite
scale without evaluating an enormous Wright series. Keep the deviance in a
form that avoids the raw ratio. Concentrated cases also need AD coverage:
at `(p,mu,phi,y)=(1.5,1.,1e-200,1.)` the value is finite but the power
and dispersion gradients are NaN.

### R11 P2 Quantile floor handling zeros representable normal results

Locations: [`quantiles.py:240`](../src/chebax/_src/recipes/quantiles.py#L240)
and [`quantiles.py:439`](../src/chebax/_src/recipes/quantiles.py#L439).

With x64, `betaincinv(1., 1., 4e-308)` and `gammaincinv(1., 4e-308)`
both return zero. The uniform and exponential quantiles are approximately
`4e-308`, above float64's smallest normal value, `2.2250738585072014e-308`.
The `lim.lo + 0.5` test classifies a band of valid roots as underflow and
bypasses the residual check. Decide underflow from the residual at the actual
representable boundary, rather than a half-unit band in log coordinates.

### R12 P2 Lambert W silently loses accuracy near maxfloat

Location: [`lambertw.py:41`](../src/chebax/_src/recipes/lambertw.py#L41).

At `np.finfo(float).max`, the principal branch returns
`703.2270032599552`; mpmath at 50 dps gives `703.2270331047702`.
The Halley denominator's `exp(w) * (w+1)` overflows even though the root
is finite, so updates stagnate at the initial approximation. Scale the
iteration or solve a logarithmic residual, and check convergence at the
largest finite input.

## Maintainability names and organization

Mathematical names are generally appropriate within formulas. The clearest
structural pattern is the generator/table/runtime split, supported by shared
reconstruction helpers and the immutable `Recipe` protocol. A broad rename or
new abstraction over every family would obscure those strengths.

| Gap | Evidence and consequence | Direction |
| --- | --- | --- |
| Inconsistent normalization boundary | `float_params`, inverse JVPs, and NumPyro each implement different parts of the scalar policy; R3 to R5 expose user-visible differences | One normalization boundary before AD, with explicit public argument names |
| Family ownership is obscured | The 788-line `quantiles.py` also owns Student-t forward/log-CDF evaluation and reconstruction, while `stdtr_gen.py` and `stdtr_table.py` have no matching runtime module | Move Student-t family implementation behind a cohesive internal module while preserving exports |
| Shared helpers have redundant names | `quantiles.py` imports `canon_float` as `_canon`, aliases `eval_betainc`, and retains an unused `_bt` import and `tensor_coefs_traced` alias | Keep shared helper names consistent and remove unused imports and aliases |
| Domain metadata depends on runtime | `domains.py:28` imports `gammainc_large` for an interval bound; several recipes import domains inside factories | Source interval bounds from metadata below the runtime layer |
| Operational history substitutes for reference docs | Rules and current behavior were scattered across `CLAUDE.md`, `PROJECT.md`, the recipe guide, and dated review dispositions | Use the new architecture and style guides as the current contributor contract |
| Architecture rules lack automated coverage | CI has numerical and extras checks, but no general dependency-layer, naming, or formatting check | Add focused import checks and a reviewed formatter/linter policy in a separate implementation change |

NumPyro constructors also reject size-one shape arrays while the README's
uniform-parameter description allows them. Its `cdf(nan)` returns `1.0`
in all three truncated classes. Those input-policy gaps should join the
contract matrix when normalization is consolidated.

The recipe guide's absolute artifact-equivalence claim, scalar-check wording,
and derivative-factory taxonomy were corrected in this documentation change.
The guides preserve the useful numerical design explanations while moving
current contracts out of the project history.

## Validation and follow-up

Focused reproductions used the `open-source` conda interpreter, the CPU JAX
backend, `PYTHONPATH=src`, and x64 unless stated otherwise. The NumPyro R1
case was reproduced with normal JIT settings as well as disabled JIT.
The test-blindness check changed objects only in a child process; no test or
runtime source was edited.

The following relevant existing selection passed, demonstrating that those
checks do not cover the new failures:

```sh
JAX_PLATFORMS=cpu python -m pytest -q \
  tests/test_contracts.py tests/test_int_params.py \
  -k 'emitted_names_are_valid or limits_at_infinity or (integer_parameter_matches_float and stdtr and python)'
# 6 passed, 100 deselected
```

The full numerical and regeneration suites were not run for this
documentation-only change. The review is evidence from source inspection and
focused executions, not a proof of every claimed accuracy bound.

Fix R1 and the NaN-blind tests first, then consolidate input normalization and
extend the shared contract matrix. Follow with the grouping, integration,
baking, and extreme-range fixes. Refactor module ownership after these
behaviors are covered, so the organization change has a clear preservation
target. Runtime fixes and automated style enforcement are follow-up work.

## Disposition

Every confirmed finding is fixed. Each runtime fix has a regression test
that fails on `dcdb931` and passes after; R2 is itself a test fix. Metric conventions are unchanged: references are
mpmath at 40 dps or more, or an exact identity, and bars sit at about 4x the
measured worst case.

| # | Disposition |
| --- | --- |
| R1 | The truncation normalizer and `cdf` select the tail's operands before the log difference, so the unused pair is never differenced. Gamma(3) on [1000, 1001] now has shape gradient 8.182020317e-5, the reference to 1.1e-11. Four intervals whose other-tail logs round to one float (both gamma tails, a beta, a Student-t at nu = 200) are tested against mpmath's derivative of the mass taken as one integral: worst 4.9e-11 absolute, from the beta's shape derivative. |

| R4 | The three inverse CDFs moved their rules to private names behind `float_params`, as the Student-t functions already were, so a size-one parameter is a scalar before its tangent exists. `test_contracts.py` differentiates every uniform-parameter entry point through a size-one parameter at a scalar point; five entry points were added to that list. |
| R5 | `ChebSeries` and `PiecewiseCheb` promote an integer evaluation point to the coefficient dtype before the custom JVP. |

The value comes from the live lane alone. Forward and reverse match the per-element loop, +inf included, also where an empty group copies the singular element. Gradients of padded elements can differ from the loop in the last ulp, since the shares are 1/k. |

On the existing grid the worst cases moved to 3.3e-13 for values (2.4e-13 before) and 3.1e-16 for d/dmu (3.4e-15), with d/dphi, d/dy and d/dp no worse. |

## Found while fixing, not addressed

- XLA on the CPU flushes subnormals and folds a division by a constant into
  a multiplication by its reciprocal. A series on a domain whose half-width
  exceeds 2^1022 (width over about 9e307) therefore evaluates to 0 for
  vectorized input under jit, as does a baked artifact run under jit. The
  scalar evaluations in `test_extreme_finite_domains_evaluate` do not see
  it. No recipe uses such a domain.
- `gammaincinv` and `gammainccinv` return nan from about a = 1e16 up
  (checked at 1e100 and 1e300), on `dcdb931` as well: the solver's log
  density a v - x - ln Gamma(a) cancels terms of size a ln a. The docstrings
  promise every a > 0; the tests reach a = 1e6.
